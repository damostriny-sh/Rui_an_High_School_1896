# GAME_MASTER — 当前项目基线

## 状态与权限

当前（2026-11-15 更新）：前期创意设计已交付，用户已选定 Route A（D010–D014）；进入前期收尾，任务见 [CURRENT_SPRINT.md](CURRENT_SPRINT.md)。本文件即路线图中的 GAME_BIBLE（D017）。

原则：先理解全局与创意发散，再收敛设计、建立生产流程，随后用小型原型检验流程，最后扩展内容。不能先设计庞大流水线再一次性实现全游戏。

用户是作者和最终决策者，决定意义、审美、范围及重大方向。ChatGPT 负责总协调、提示词、设计整合、技术架构、任务分配和验收；这不意味着垄断创意。

Claude 在创意阶段承担创意主导：提出核心体验、创作支柱、叙事与视觉方案，挑战平庸方案。进入设计收敛阶段则切换到审查任务，检查一致性、玩家行为、成本与依赖；可由用户选择另一个 Claude 会话或模型承担，不要求必须使用特定型号。ChatGPT 补充技术与范围审查并统一决策入口。模型名称不代表已验证的能力或已接通的自动协作。

进入执行阶段后，Claude 或其他执行者按已批准任务实施。一个任务只有一个实施者；任何角色可以提出修改建议，但不能默默更改主文档。

## 已确认的创作内核

- 校园主题、第三人称、战斗与生存的独立游戏。
- 现实校园与意识空间在特定条件下切换，切换推动剧情。
- 做题进入意识空间，题目拟物化（D013）；解法成为技能，正确方法能更有效地战胜敌人。
- 遭遇采用 Route A：一道题是一个可行走、可操作的房间；题目是由手托住的物件排列，不做生物；让手松开即取胜，不需要还击（D010、D011、D013）。
- 首个切片：现实侧为陶舍（Taoshe）茶室，意识空间侧为 sipping_mountain_front（D012）。
- 跳题扣生命；长期成绩下降扣理智；校园娱乐活动恢复状态。
- 课程、作业、考试、吃饭、休息构成日程。
- 荒诞与无奈的后现代主题，以及存在主义的一抹亮色。
- 现实校园明亮、高饱和、半写实；意识空间遵循用户插画的石墨超现实语法，详见 ../01_art/ART_DIRECTION.md。
- 首个空间样板主参考为 reference/Aesthetic/sipping_mountain_front.JPG。图中层叠结构是肢体，不是山壁。

## 阶段和出口

完整生命周期与分工见 [PRODUCTION_ROADMAP.md](PRODUCTION_ROADMAP.md)。核心循环先设计与验证，随后整合垂直切片；轻量生产流程前期建立，自动化根据原型和切片的证据逐步扩展。剧情、整合与试玩贯穿制作。

| 阶段 | 产出 | 出口 |
|---|---|---|
| 理解与创意发散 | 对固定要求的复述、两条可比较的体验路线 | 无误读；每条路线有具体玩家行为与代价 |
| 设计收敛 | 推荐路线、核心循环、单段体验脚本、风险与取舍 | ChatGPT 审查；用户确定体验和审美方向 |
| 生产流程 v0.1 | 输入/输出、负责人、依赖、验收、失败回退 | 可以产出一场战斗和一个空间样板，不依赖虚构工具能力 |
| 小型验证 | 战斗原型与肢体空间样板 | 玩法、风格和流程均经过实际验证 |
| 纵向切片 | 校园—战斗—返回—恢复—剧情反馈 | 可玩、可保存且有代表性 |
| 内容扩展 | 复用模块、配置和经验证的生产工具 | 单项成本可预测，持续试玩迭代 |

艺术流程：参考 → 风格规则 → 场景配方 → 构图锚点/灰盒 → 模块化资产 → 材质光照 → 实机对照 → 审美验收。
玩法流程：体验目标 → 玩家行动 → 规则与状态 → 原型 → 试玩 → 修订。
技术流程：选定设计 → 最小模块/数据约定 → 实现 → 验证 → 整合。

## 文档治理

最新用户决定优先于本文件，本文件优先于候选和历史文档。具体领域遵循已采用的对应规格。冲突必须报告并记录处理，不凭文件更新时间猜测需求。

候选提案写在 docs/02_design_proposals；每项标明来源、假设、状态。ChatGPT 记录采用决定，涉及核心方向由用户选择。设计采用不等于功能完成；代码存在不等于验证通过。

避免同一事实复制到多份文档。当前任务书引用基线，不重建另一份“游戏宪法”。负责人在批准范围内处理实现细节。各 AI 模式、权限与审批流程见 [AGENTS.md](../../AGENTS.md)。
